# Blind Test Separation Checklist — چک‌لیست جداسازی آزمون کور

- [ ] مجموعهٔ ارزیابی با توسعه (غبن، عذره، خانواده‌های C1/C2) هیچ اشتراک مسئله/خانواده‌ای ندارد.
- [ ] کلید فقط نزد ارزیاب مستقل است؛ در هیچ شاخهٔ GitHub، فایل مشترک، یا حافظهٔ پروژه نیست.
- [ ] هش کلید پیش از اجرا نزد شخص ثالث/مهر زمانی ثبت شده است.
- [ ] فهرست منابع افشاکنندهٔ پاسخ (شروح حاوی حل مسئله) از مجموعهٔ ارزیابی کنار گذاشته شده است.
- [ ] معیارها و آستانه‌ها پیش از مشاهدهٔ هر خروجی، کتبی و مهر شده‌اند.
- [ ] هیچ تنظیم قاعده‌ای پس از مشاهدهٔ خروجی انجام نمی‌شود؛ هر تغییر = ابطال آزمون و شروع مجموعهٔ تازه.
- [ ] خروجی‌های ناموفق با همان قالب موفق‌ها بایگانی می‌شوند.
- [ ] حل اختلاف داوران مستند و بدون آلودگی مجموعه انجام می‌شود.
- [ ] پس از افشا، مجموعه در اسناد پروژه برای همیشه «توسعه» برچسب می‌خورد.
- [ ] هیچ‌یک از Muse/ChatGPT به کلید، پیش یا پس از اجرا، دسترسی ندارند (دسترسی پس از اجرا فقط به گزارش داوریِ ارزیاب است).
