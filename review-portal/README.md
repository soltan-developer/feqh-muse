# میز داوری اجتهاد | Feqh Muse Scholar Review Portal

وب‌اپ فارسی، واکنش‌گرا و کاملاً ایستا برای بررسی علمی ۱۰ نامزد قاعده روش اجتهادی شیخ مرتضی انصاری توسط پژوهشگر اصلی.

**وضعیت:** PRIMARY_RESEARCHER_SELF_REVIEW / RESEARCH_ONLY / NO_HISTORICAL_ADMISSION.

## راه‌اندازی محلی

از ریشه ریپو:

    python -m http.server 8080 --directory review-portal

سپس نشانی http://localhost:8080 را در مرورگر باز کنید. باز کردن مستقیم index.html با file:// ممکن است به علت محدودیت مرورگر در دریافت فایل JSON درست کار نکند.

بدون نیاز به Node، دیتابیس، سرویس خارجی، کلید API یا نصب پکیج قابل اجراست. همه فایل‌های موردنیاز در این پوشه هستند:

- index.html — پوسته سایت
- styles.css — طراحی RTL و واکنش‌گرا
- app.js — داوری و ثبت شخصی، واردکردن و خروجی گرفتن
- data/review-data.json — داده پژوهشی استخراج‌شده از C4، ۱۰ پرونده، ۳۴ نقل کوتاه

## انتشار در GitHub Pages

### مسیر آسان: مخزن مستقل

۱. یک مخزن GitHub **با سطح دسترسی مورد نظر** بسازید.
۲. محتویات پوشه review-portal را به ریشه آن منتقل کنید؛ یعنی index.html باید در ریشه قرار بگیرد و پوشه data کنارش باشد.
۳. در Settings → Pages، در صورت فعال بودن Pages، گزینه Deploy from a branch را انتخاب کنید، شاخه main و پوشه /(root) را تنظیم کنید.
۴. پس از انتشار، سایت را با مرورگر باز کنید. آدرس از نوع https://ACCOUNT.github.io/REPO/ خواهد بود.

**هشدار مهم حریم خصوصی و مجوز انتشار:** فایل data/review-data.json شامل نقل‌هایی از کتاب‌ها و بخش‌هایی از پرونده پژوهشی خصوصی است. هر کسی که به GitHub Pages منتشرشده دسترسی داشته باشد می‌تواند این داده را دریافت کند. **خصوصی بودن مخزن لزوماً به معنی خصوصی بودن وب‌سایت Pages نیست.** اگر داده‌ها نباید عمومی باشند، تا ایجاد کنترل دسترسی واقعی، سایت را فقط محلی اجرا کنید یا از میزبان دارای احراز هویت واقعی استفاده کنید. رمز ساده JavaScript برای حفاظت اطلاعات کافی نیست.

### مسیر موجود در مخزن feqh-muse

این سایت در شاخه feature/scholar-review-portal-v1 داخل review-portal/ ثبت شده است. یک workflow دستی .github/workflows/review-portal-pages.yml هم برای انتشار همین پوشه وجود دارد. **صرفاً بعد از بررسی اجازه انتشار داده‌ها،** و وقتی workflow در شاخه پیش‌فرض در دسترس است، از Actions اجرا کنید و GitHub Pages را برای GitHub Actions تنظیم کنید. اجرای workflow به معنی انتشار عمومی داده‌های داخل سایت است.

نیازی نیست کل زنجیره PRهای پژوهشی را برای انتشار آزمایشی این وب‌اپ ادغام کنید؛ انتقال پوشه به یک مخزن مستقل ممکن است سریع‌تر و تمیزتر باشد.

## روش داوری

۱. نام خود را در بالای صفحه وارد کنید (نام برای تکمیل نهایی لازم است).
۲. یکی از ۱۰ پرونده را از فهرست انتخاب کنید.
۳. در «پرونده و مبانی»، شش جزء و شناسه‌های شواهد را بررسی کنید.
۴. در «متن و شواهد»، نقل‌های کانونی و سیاق کوتاه را ببینید؛ برای داوری مستقل به کل سیاق در کتاب مراجعه کنید.
۵. در «داوری و نظر شما» برای هر شش جزء **تأیید / رد / اصلاح / تعلیق** انتخاب کنید. برای تصمیم‌های غیر از تأیید هر جزء، دلیل دست‌کم ۸ نویسه لازم است.
۶. درباره کل قاعده نیز نتیجه و دلیل حداقل ۱۲ نویسه ثبت کنید.
۷. دکمه «ثبت و تأیید ثبت نظر این پرونده» را بزنید؛ تکمیل فقط بعد از این عمل محسوب می‌شود. پس از هر تغییر جدید، آن پرونده دوباره نیازمند ثبت نهایی است.
۸. با «دریافت گزارش» از کل تصمیم‌ها فایل JSON یا MD بگیرید. برای ادامه کار با ChatGPT، **فایل JSON را در گفت‌وگو پیوست کنید**.

## واردکردن و بازگردانی

در زبانه «پرونده و مبانی» دکمه «واردکردن گزارش» در دسترس است. خروجی JSON سایت قابلیت بازگردانی دارد و فقط با نسخه C4 هم‌هویت پذیرفته می‌شود. از فایل‌های متفرقه استفاده نکنید.

ذخیره خودکار از localStorage همان مرورگر استفاده می‌کند. این داده به سرور ارسال نمی‌شود و رمزگذاری‌شده نیست؛ بنابراین روی مرورگر اشتراکی استفاده نکنید. پاک‌کردن داده مرورگر ممکن است یادداشت‌ها را از بین ببرد؛ دوره‌ای خروجی JSON بگیرید.

## تعهدات علمی

- «تأیید» در این سایت صرفاً **نظر پژوهشگر اصلی** است، نه تأیید مستقل دو داور.
- هیچ قاعده‌ای در engine2/ یا جداول تاریخی approved نمی‌شود.
- اطلاعات چاپ هر سه منبع در داده C4 نامعلوم است.
- شواهد از رجیستر کانونی پژوهش C4 هستند؛ سایت در زمان مرور کل کتاب را واکشی یا مستقل مقابله نمی‌کند.
- اختلافات CE-01 و OQ-C1-01 و فقدان استقلال بعضی شواهد به‌صورت خودکار حل نمی‌شوند.
- خروجی دارای research_qualification_effect: NONE و historical_admissions: 0 است.
